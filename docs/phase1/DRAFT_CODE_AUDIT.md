## 3. معمارية الكود الحالي

```
app ──► core:design
 │
 ├──► automation:actions ──► core:model
 └──► domain:providers  ──► core:model   (اعتماد غير مستخدم في app، يُحذف)

domain:agent ──► automation:actions, automation:policies, domain:providers
domain:mission ──► automation:actions
automation:policies ──► automation:actions
```

- وحدات المحرّك الستة **Kotlin خالص** (لا تعتمد على Android)، وتُختبر على أي حاسوب.
- `settings.gradle.kts` يضم وحدات Android فقط عند وجود Android SDK، ليمكن اختبار المحرّك في بيئتي السحابية.
- كل إضافات Gradle في classloader واحد (كان شرطاً لنجاح البناء على CI).

## 6. مقارنة المسودة بالمعمارية المعتمدة (المرحلة الأولى)

المرجع: [المعمارية](ARCHITECTURE.md). باختصار: المسودة تطابق **المبادئ** (محرك حتمي، كتالوج مغلق، حالات تنفيذ منفصلة، عدم تكرار الإرسال، عزل المحتوى غير الموثوق)، لكنها كُتبت قبل [استراتيجية الأتمتة](../AUTOMATION_STRATEGY.md)، فهي **متحيزة لنموذج "جهّز ثم اضغط يدوياً"** وتنقصها طبقات مهمة.

## 7. ما يُحتفظ به وما يُعدّل وما يُعاد بناؤه

| الجزء | القرار | السبب |
|---|---|---|
| `ExecutionOutcome` (محاولة/مقبول/مكتمل/متحقق/فشل/رُفض/مجهول) | ✅ يُحتفظ به | يطابق شرط "لا خلط بين المحاولة والنجاح" |
| `RiskLevel`, `MissionState`, `ActionId`, `MissionId` | ✅ يُحتفظ بها | |
| `MissionStateMachine` + اختباراته | ✅ يُحتفظ به | جدول انتقالات صريح ومختبر |
| `CrashRecoveryAdvisor` | ✅ يُحتفظ به ويُوسّع | يُضاف التعامل مع حالة "مجهول" وسجل الأدلة |
| `ActionRegistry` + `ParamSpec` + التحقق من المعاملات | ✅ يُحتفظ به | يُضاف نوع معامل لمعرّف المحادثة/جهة الاتصال |
| `PlanValidator` | 🟡 يُعدّل | يُضاف فحص توفر القدرة على الجهاز والصلاحيات قبل الموافقة |
| `PromptAssembler` | ✅ يُحتفظ به | |
| واجهات `AIProvider` و`ProviderError` | 🟡 تُعدّل | إضافة تقدير التكلفة، وإلغاء الطلب، وإعلان دعم المخرجات المهيكلة لكل نموذج |
| `ProfileSelector` | 🟡 يُعدّل | العتبات الرقمية مبدئية بلا قياس؛ تُربط بنتائج تقييم حقيقية في المرحلة 4 |
| `StructuredOutputParser` | 🟡 **يُعدّل — وجدتُ خللاً** | إصلاح "علامات الاقتباس الذكية" يستبدل `“ ”` في **كل** النص، بما فيها داخل قيم النصوص، فقد **يغيّر محتوى رسالة** المستخدم (مثل اقتباس عربي داخل رسالة). هذا يخالف قاعدة "الإصلاح لا يغيّر المحتوى". الإصلاح: تطبيقه فقط على علامات تحيط بالمفاتيح والبنية، مع اختبار يثبت ذلك |
| `Capability` (enum ثابت) | 🔁 يُعاد بناؤه | القدرات يجب أن تعلنها المحوّلات (adapters) ديناميكياً حسب الجهاز والتطبيقات المثبتة والحسابات المربوطة |
| `GenesisPermission` (enum صغير) | 🔁 يُعاد بناؤه | يحتاج نموذج صلاحيات بثلاثة أنواع: صلاحيات Android وقت التشغيل، وصول خاص من الإعدادات، صلاحيات OAuth للخدمات |
| `ApprovalPolicy` + `StandingGrant` | 🔁 يُعاد بناؤه | الإذن المسبق يجب أن يُحدد بالمحادثة/جهة الاتصال، والمدة، وحد العدد، وقيود المحتوى (مثل: لا مبالغ ولا مواعيد)، وليس بالمهمة فقط |
| `BuiltInActions` (8 إجراءات) | 🔁 يُعاد بناؤه | يُضاف: الرد عبر الإشعار، Gmail، Pages، Telegram Business، التقويم المباشر، الملفات؛ ومراجعة مستويات الخطورة (الرد التلقائي = عالٍ) |
| `Mission` (خطوات متسلسلة) | 🟡 يُعدّل | الخطة تدعم الاعتماديات بين الخطوات لكن المهمة تنفذ بالتسلسل فقط؛ يُضاف دعم المهام الطويلة المراقِبة ("حتى أعود") |
| نظام التصميم (`Color`, `Theme`, `Components`) | ✅ يُحتفظ بالألوان والمقاييس | نسب التباين محسوبة؛ الخطوط تُستبدل بخطوط مضمّنة |
| شاشة `HomeScreen` | 🔁 يُعاد بناؤها | كانت شاشة مؤقتة تعرض الكتالوج؛ تُبنى وفق تصميم الشاشات في المرحلة 2 |
| إعداد البناء وCI | ✅ يُحتفظ به مع إصلاح | مُثبت على CI؛ يُحذف اعتماد `app` غير المستخدم على `domain:providers`، وتحديث إصدارات Actions |

**الخلاصة:** يُحتفظ بحوالي **60%** من الكود كما هو أو بتعديلات صغيرة (النواة الحتمية والاختبارات)، ويُعاد بناء **قرابة 40%** (القدرات، الصلاحيات، الأذونات المسبقة، الكتالوج، الشاشة) لأن استراتيجية الأتمتة الجديدة غيّرتها. لن يُدمج شيء قبل موافقتك على المرحلة الأولى، وسيُدمج في المرحلة الثانية **مع** هذه التعديلات وليس كما هو.
